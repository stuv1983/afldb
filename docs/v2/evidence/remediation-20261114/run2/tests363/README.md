### Refusals (all unit-tested in `tests/dsn-policy.test.ts`, 58 tests, DB-free, injected connection that fails the test if opened)

- base DSN not a postgres URL, not ending `_test`, port 5432 **or no port** (the default 5432), or carrying a libpq redirect (`host`, `service`, ...): refused **before any connection**; messages carry check names, never credentials;
- malformed prefix (empty, uppercase, punctuation, too long, an injection attempt): refused at name generation, parse and sweep;
- drop: only a name in **this process's** registry of names it generated and created, still of the generated shape for the prefix, ending `_test`, and **never the DSN-named base** (each condition alone refuses);
- sweep: bound below 60 minutes refused, so it can never reap a live run's database; only same-prefix generated-shape `_test` names older than the bound by the stamp in the name, carrying the base's marker comment, never the base.

Mutation proof (`mutation-proof.txt`, a throwaway worktree of the final commit, file restored byte-identical): removing the port-5432 refusal fails 3 tests; the
`_test` refusal 2; the "generated by this process" refusal 2; prefix validation 9; "the base may not be dropped" 1.

### Credentials, template-in-use, failure handling

- The test role `afldb_owner` is NOCREATEDB by design (`tools/v2/isolated-pg.ts` creates every role `NOCREATEDB`), so creation uses an **admin connection** to the same host and port, database `postgres`.
  The wrapper passes only the role name and the **path** of the cluster's `secrets/superuser.pw` (`AFLDB_TEST_PER_FILE_ADMIN_USER`, `AFLDB_TEST_PER_FILE_ADMIN_PASSWORD_FILE`); the
  password is read from the file per connection and never enters any environment, so no test, imported module or child process can see it. Neither variable contains `DATABASE_URL`, which
  keeps `isolated-pg run` (it strips every `*DATABASE_URL*` variable) from removing them. With neither set the base DSN's own role is used (works only if it has CREATEDB).
- **Template in use.** `CREATE DATABASE ... TEMPLATE` fails while any other session is connected to the base. Creation is serialised across processes by a session advisory lock keyed on the base name; an "accessed by other users" refusal (55006) is
  retried up to 20 times with 0.5-3 s back-off, then fails naming the sessions holding the base (pid, role, application name, state). No session is ever terminated on the base. In per-file mode nothing of the run connects to the base (the audit option is the only exception, briefly, between files).
- **Teardown even on failure.** The setup file's `afterAll` runs whether the file's tests passed or failed. A file whose tests are **all skipped never runs any `afterAll`** (found in the first full run: six fully-skipped files leaked six 407 MB databases), so every created name is also written to a **run ledger** directory created by the
  vitest `globalSetup` (`packages/testing/src/per-file-global-setup.ts`, registered in `vitest.config.mts`), and the globalSetup teardown, in the main process, drops what is still recorded (same droppable rule; refusals are reported, never dropped). Verified: 6 databases reaped from a run of the six skipped files.
- **Crash (SIGKILL, reboot).** Nothing runs; only prefix-named databases are left, 407 MB each. `sweep-per-file-dbs.sh` (documented below) removes them.
- **Run-wide serialisation.** The vitest config keeps `fileParallelism: false`; with parallel files the advisory lock still serialises creation and the ledger is shared.

## Residuals

1. **Skipped-file databases live until the run ends** (6 x 407 MB here). Consequence: transient disk and database-count peak; existing protection: the end-of-run reaper, the sweep, 481 GB free; operator action: none; alternative: reap ledger entries whose owning worker pid is gone when the next file starts (not done: adds a liveness rule to the drop path and a requalification). Recommended disposition: accept.
2. **A SIGKILL/reboot leaves prefix-named databases** (407 MB each) until the sweep runs; only the 60-minute age bound separates "left by a crash" from "a very long live file". The longest files observed run 244 s (`gridley-corpus`), 210 s (`draftguru-import`) and 168 s (`awards-reload-links`, whose hooks allow 900 s). Operator action: run `sweep-per-file-dbs.sh` (dry run first) after a crashed run, never while a run is in progress.
3. **The audit's "residue" cannot distinguish a rewritten-identically row from a changed one** and does not see schema objects or sequences. It informs the registry; it does not gate anything.
4. **`=1` depends on a maintained list.** `=all` does not; the registry has a test that every entry exists and that every fixture-season owner is in it, but a new committing suite must still be added.
5. **Per-file mode runs +16 % slower** and needs the cluster superuser (password file path) because the test role is NOCREATEDB. Alternative considered and rejected: `ALTER ROLE afldb_owner CREATEDB` (changes the isolated cluster's role contract, `NOCREATEDB` for every role, which `privileges.test.ts` asserts for `afldb_app`).
