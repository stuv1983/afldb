## 4. Rollback (application only; never touches data)

**Triggers.**
- The unit is not active after one `reset-failed`.
- `status --expect` or `post-install-check.sh` FAIL.
- Public 5xx, or the 503 gate message.
- Journal errors.
- A raw-head control misbehaving (anonymous 200 where a 404 is expected, or a 5xx).

A CLI exit of 1 or 2 alone is **not** a rollback trigger. The application still serves correctly; it means the env or
fan-out needs diagnosis. Record it and go to the owner.

**Sequence.**
1. `node deploy/release.mjs rollback --attended --to c8d4202a4cb3-aATnIlFOIQjq2z5oDdoHC --ledger-head <the P1 ledger head>`
   switches the `current` link back. It rebuilds nothing.
2. **Owner:** `sudo systemctl restart afldb`.
3. `node deploy/release.mjs status --expect c8d4202a4cb3-aATnIlFOIQjq2z5oDdoHC` PASS, then
   `bash deploy/post-install-check.sh c8d4202a4cb3-aATnIlFOIQjq2z5oDdoHC <NEW BUILD_ID>`.
4. Raw-head control: `/brownlow/2026` still 200 with the 7R3 title and winner. The data is unchanged by any rollback.

**The env lines are harmless under `c8d4202a`.** At that revision the readers of `readRevalidateConfig` are three:
- the loopback, secret-gated `/api/internal/revalidate-season` route (ISSUE-134), which refreshes `/seasons/<y>` only;
- the Brownlow admin actions' season fan-out;
- `settle-afltables`, whose timer is not active on production (R0).

So the lines only make those refreshes reach every worker. Removing them is optional. To remove them, restore the `.env` backup taken in step 5
and restart once more, attended.

The checkout left at `7d92042f` is harmless, because the release tree is what is served.

## 5. Risks

- **Env omitted or half-configured.** The release is safe, but every fan-out is inert. Half configuration makes the CLI
  exit 2 and the fan-outs log "misconfigured". The step 5 counts and acceptance 3 and 4 catch both.
- **The secret leaking.** Its blast radius is re-rendering a season's two pages. The route takes only loopback and an
  integer year. Keep the value out of command lines; the CLI reads `.env`.
- **The restart itself.** This is the same exposure as 7R3: a short outage, plus a cold per-worker ISR cache. The first
  requests regenerate pages.
- **The award fan-out adds up to 3 loopback POST rounds** after each awards or Coleman mutation. It is best-effort and
  never fails the admin request.
- **Not exercised end to end:** a request naming a season only through `/awards/<slug>/<yyyy>`. Unit tests cover it.
- **DEV is not production.** DEV ran 4 workers with indexing off. Production has 2 workers. The robots check uses
  production's own 7R3 baseline.
