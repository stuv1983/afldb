## 3. Production precondition (owner step; release is inert without it)

R0 (read-only, 2026-11-22 02:52 AEDT) found **neither** `AFLDB_REVALIDATE_URL` **nor** `AFLDB_REVALIDATE_SECRET` in the
production checkout `.env` (the unit's `EnvironmentFile`) or in the running `afldb` processes (MainPID + 2 workers)
(`R0-SITTING-20261122.md`, "Environment presence"). Without both, every
fan-out (the Brownlow publish action, the awards follow-up and the CLI) is inert and the release behaves as today: only the
worker that served the action is refreshed, and a cached `/seasons/<y>` or `/brownlow/<y>` 404 on another worker can be
regenerated as a 200 page with the "Page not found" title and `noindex` for up to one ISR window (1 h).

In the release window, after the new release is promoted and before the restart (`docs/deployment.md` §7c):

```bash
cd ~/projects/afldb
echo "AFLDB_REVALIDATE_URL=http://127.0.0.1:3100" >> .env
echo "AFLDB_REVALIDATE_SECRET=$(openssl rand -hex 32)" >> .env
sudo systemctl restart afldb
grep -c '^AFLDB_REVALIDATE_URL=' .env; grep -c '^AFLDB_REVALIDATE_SECRET=' .env   # each 1; never print the value
```

The AFL API settle units keep `UnsetEnvironment=AFLDB_REVALIDATE_SECRET` (D-232-3); no `deploy/*` file changes.
