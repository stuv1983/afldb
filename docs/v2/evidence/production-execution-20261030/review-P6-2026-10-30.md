## Method

Every claim in the package and in a script's own comments was checked against the file on disk, not against its description:
exact output strings the scripts grep (`AFLDB migrations -> prod (…)`, `PENDING  `, `0 pending.`, `Applied N migration(s).`,
`I|transaction_read_only|on`), when `migrate.ts` prints its target line relative to connecting (after the ledger read: the
one-attempt marker is sound), exit-code propagation under `set -uo pipefail` without `-e` (every command that matters is
followed by an explicit check or `PIPESTATUS`), credential paths (libpq variables in env prefixes only; `safeTarget` prints
no password; `H9` control greps every log), DSN identity enforcement before any write, refusal paths, and the format
compatibility of the host read-back (`psql -At -F tab` through `q`) with the isolated read-back (`psql-owner.mjs`): both
SQL files set `\pset format unaligned`/`tuples_only` and emit one column, so the outputs are byte-comparable. The controls
were examined for vacuous passes (setup that silently applies nothing, wrong subject, missing file read as success).

Verified sound (no finding): identity block and ledger digest form (host `q -At -F tab` lines == `ledger-tsv.mjs` bytes);
`hs_backup` series-count and ledger-before/after checks; sidecar `wx`; `hs_arel` pre-write chain and no-retry marker;
`restore-test.sh` targets `afldb_restore_test` only; gate tools write reports with `wx` and never exit 0 on a crash;
`rehearsal-summary.mjs` requires every exit code and `T.privileges.json` 43/43 and cannot PASS on a missing item;
`snapshot-compare.mjs` refuses empty captures and scope mismatches (exit 2, nothing written); PullIso verifies each file
against the run's evidence manifest and refuses a non-`PASS*` rehearsal; D-controls assert the class list, so a setup that
inserted nothing cannot pass D1; the isolated bootstrap (`isolated-pg.ts:316-326`) mirrors `00_install_postgres` so clone B's
`public` schema facts are comparable with production's.
